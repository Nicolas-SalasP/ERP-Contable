Veredicto general

Tenri ERP es un sistema bien construido para su etapa: arquitectura DDD por dominios, 204 archivos de test, CI/CD con PHPStan + PHPUnit, Sentry, backups, cifrado de material SII en reposo y RBAC granular en dos capas. Los riesgos detectados no son de diseño roto, sino de garantías que aún dependen de disciplina manual en lugar de capas centrales fail-safe. Cerrar P0/P1 deja al sistema listo para escalar contribuyentes y para conectar TGR / Previred / Cajas con seguridad regulatoria.

Fortalezas confirmadas

  • Cifrado SII en reposo: certificados .pfx, contraseñas, clave RSA y XML del CAF cifrados con Crypt + marcados $hidden.
  • SSO con HMAC-SHA256 con timestamp + nonce (anti-replay).
  • RBAC en dos capas: gate por permiso en ruta + lógica relativa por instancia en controller.
  • Deploy por SSH/SCP con claves en GitHub Secrets (el README dice "FTP": desactualizado).
  • Sin .env/certificados/claves ni secretos reales en el árbol ni en 347 commits de historial.
  • CORS con orígenes explícitos (sin wildcard) · bcrypt rounds 12 · partida doble validada · DECIMAL(15,2).

Preparación para TGR · Previred · Cajas de Compensación

Regla de oro: resolver el aislamiento multitenant (P0/P1) antes de conectar datos previsionales/fiscales — una fuga cross-tenant ahí sería incidente regulatorio.
  • Base ya existente: dominios DDD aislados + patrón de integración por eventos (outbox) en Inventario y SII.
  • Generalizar la capa de credenciales cifradas del SII como servicio común reutilizable por cada organismo.
  • Adaptador por organismo (interface + adaptadores sandbox/producción) con feature flags por plan.
  • Cola + outbox para toda integración externa (idempotencia, reintentos, dead-letter); exige cache/locks en database/redis.
  • Verificación criptográfica de respuestas y auditoría a nivel de campo como requisitos transversales.
